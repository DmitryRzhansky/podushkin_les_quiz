# Земельные участки под Хабаровском

Интерактивный квиз для выбора земельного массива и заявки на осмотр. На широких экранах вопросы используют компактную сетку, а на телефонах интерфейс складывается в одну колонку. Ответы сохраняются при возврате; переход к следующему вопросу происходит по кнопке. Сайт написан на HTML, CSS и Vanilla JavaScript без сборки, npm, сервера и внешних виджетов.

## Запуск

Откройте файл index.html в браузере. В режиме просмотра квиз работает локально; форма останется в демонстрационном режиме и не отправит данные.

Для настоящей отправки разместите папку сайта на обычном статическом хостинге по HTTPS и подключите API в js/config.js. API должен разрешать запросы с домена сайта через CORS.

## Структура

- index.html — разметка страницы и оболочка квиза.
- css/style.css — адаптивный дизайн, включая правила для уменьшения анимации.
- js/app.js — автопереходы между вопросами, карточки результата, проверка полей и отправка заявки.
- js/translations.js — тексты на русском и упрощённом китайском (zh-CN).
- js/config.js — адрес API, политика, контакты и демонстрационный режим.
- assets/images/ — фотографии и схемы из действующего квиза, сохранённые локально.
- assets/fonts/ — Manrope и локальные шрифты Font Awesome.
- assets/icons/fontawesome.min.css — локальная таблица стилей Font Awesome 6.5.2.
- ASSETS.md — источники, назначение и ограничения материалов.

## Настройка API

Откройте js/config.js и измените настройки:

- apiUrl — полный HTTPS URL обработчика заявок.
- demoMode — установите false после подключения и проверки API.
- privacyUrl — действующая политика обработки персональных данных.
- representative — актуальные телефон, адрес электронной почты и phoneHref.
- resources.videoUrl — ссылка на видеооблёт, если она будет подтверждена и доступна.
- resources.cadastralSchemeUrl — ссылка на актуальную схему, если вместо локальной понадобится документ по ссылке.

Браузер отправляет JSON методом POST. Тело включает ответы о выбранном массиве, назначении, сроке и осмотре; имя, способ связи, контакт, комментарий, язык, согласие и параметры UTM из адреса страницы.

Пример ответа, после которого сайт покажет отдельный экран подтверждения:

    HTTP 200
    Content-Type: application/json

    {"success": true}

Обработчик должен отвечать с сайта на домен квиза по CORS. Сайт не считает заявку принятой после одного лишь HTTP-ответа: в JSON должно быть поле success: true. При ошибке или другом формате ответа посетитель увидит сообщение, что получение заявки не подтверждено.

Демо-режим включён по умолчанию. В нём отправки нет, а введённые сведения остаются только в памяти текущей страницы и не сохраняются в localStorage, cookie или аналитике. Для реального приёма заявок нужны действующий API, проверенная политика конфиденциальности и настройка CORS.

## Публикация

1. Проверьте apiUrl, контакты и privacyUrl.
2. Уточните кадастровые сведения и разрешённое использование по актуальным документам.
3. Проверьте русские и китайские формулировки у носителя китайского языка, включая согласие на обработку персональных данных и коммерческие условия.
4. Загрузите содержимое папки на статический хостинг с HTTPS.
5. Подключите API, отключите демонстрационный режим и проверьте реальный ответ {"success": true} на тестовом обращении.

Все изображения, шрифты, иконки, стили и скрипты, необходимые для отображения страницы, находятся локально. Форма обращается к сети только после явного подключения API и отключения демонстрационного режима.
